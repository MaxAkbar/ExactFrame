# ExactFrame 2.1.1

This patch improves stability when moving or resizing a frame in the **Outline area** display preview.

## Download and start

- [Windows x64 portable ZIP](https://github.com/MaxAkbar/ExactFrame/releases/download/v2.1.1/ExactFrame-2.1.1-win-x64-portable.zip) for Intel and AMD PCs.
- [Windows ARM64 portable ZIP](https://github.com/MaxAkbar/ExactFrame/releases/download/v2.1.1/ExactFrame-2.1.1-win-arm64-portable.zip) for Windows on Arm.
- [SHA-256 checksums](https://github.com/MaxAkbar/ExactFrame/releases/download/v2.1.1/SHA256SUMS.txt).

Extract the ZIP and open **ExactFrame.exe**. No installer or separate .NET or Windows App SDK installation is needed. Requires Windows 10 version 1809 or later; Windows 11 is recommended. Existing settings and saved profiles remain in `%LOCALAPPDATA%\ExactFrame\exactframe.db`.

## Fixed

- Preview redraws now wait until the current input or layout event has finished. Decorative shapes no longer receive pointer input, so rebuilding the drawing keeps the input surface stable.
- Repeated drags no longer clear the previous result text while the pointer is down. This prevents the preview from changing size and canceling the drag unexpectedly.

## Validation

- All 426 core tests passed.
- Seven native Windows preview checks passed. The same checks detected unsafe input targets and immediate visual replacement in the original preview code.
- Repeated moves on both connected displays, at 150% and 175% scaling, and resizing with the outline visible completed without a crash during local x64 checks.

These checks cover the preview interaction path. They do not establish compatibility with every display setup or recorder.

## Known limitations

All features and existing limitations from [2.1.0](v2.1.0.md) continue to apply. In particular, native ARM64 execution and saved-recording compatibility remain unverified. The downloads are unsigned, so Windows may show an unknown-publisher warning.
