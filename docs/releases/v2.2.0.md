# ExactFrame 2.2.0

Send a still capture of the main frame or an additional guide directly to SnapStudio for editing.

## Download and start

- [Windows x64 portable ZIP](https://github.com/MaxAkbar/ExactFrame/releases/download/v2.2.0/ExactFrame-2.2.0-win-x64-portable.zip) for Intel and AMD PCs.
- [Windows ARM64 portable ZIP](https://github.com/MaxAkbar/ExactFrame/releases/download/v2.2.0/ExactFrame-2.2.0-win-arm64-portable.zip) for Windows on Arm.
- [SHA-256 checksums](https://github.com/MaxAkbar/ExactFrame/releases/download/v2.2.0/SHA256SUMS.txt).

Extract the ZIP and open **ExactFrame.exe**. No installer or separate .NET or Windows App SDK installation is needed. Requires Windows 10 version 1809 or later; Windows 11 is recommended. Existing settings and profiles remain in `%LOCALAPPDATA%\ExactFrame\exactframe.db`.

## Capture in SnapStudio

Install [SnapStudio 1.2.0 or newer](https://github.com/MaxAkbar/SnapStudio/releases/tag/v1.2.0), which requires Windows 11 x64. In **Outline area**, choose **Main frame** or an additional guide under **Capture area**, then click **Capture in SnapStudio**. On first use, choose **SnapStudio.App.exe** from its extracted portable folder. ExactFrame remembers the path; **Choose app…** changes it later.

- Start SnapStudio automatically when needed and open the captured image for annotation, copy, or export.
- Capture physical screen pixels without redrawing the region. Additional guides use their actual on-screen crop rather than their planned recording output size.
- Hide ExactFrame's windows, HUD, and guides and minimize SnapStudio during capture. Restore the overlays afterward while keeping SnapStudio in front after success.
- Recover from unsupported older copies, busy dialogs, timeouts, and disconnections with an explanation and restored controls.
- Exchange bounds and status through a local, current-user-only, session-specific pipe. Images and databases remain separate, the connection makes no online requests, and the clipboard is unchanged.

Release builds also pin the .NET SDK and refresh its portable linker lock files, keeping locked restores consistent across local and CI builds.

The full region must fit on one connected display. Each side must be 4–20,000 pixels, with no more than 40 million pixels total. Finish SnapStudio's first-run setup and any open dialog before capturing. Older SnapStudio and ExactFrame releases do not include this connection. See the [setup guide](https://github.com/MaxAkbar/ExactFrame/blob/v2.2.0/docs/snapstudio-integration.md).

## Checks and known limitations

Core checks cover frame choices, app-path persistence, physical dimensions, malformed responses, correlation IDs, transport limits, cancellation, and error recovery. Local Windows x64 integration checks captured a 640 × 360 main frame and a 189 × 336 guide at 175% scaling, verified known image pixels, retained workspace focus, restored outlines, and rejected capture while SnapStudio's New image dialog was open without creating an image.

Both x64 and ARM64 portable packages are built. Native ARM64 execution, integration on other native monitor layouts and negative-coordinate displays, and saved-recording compatibility remain unverified. SnapStudio currently supplies an x64 portable package. These downloads are unsigned, so Windows may show an unknown-publisher warning. Existing limitations from [2.1.1](https://github.com/MaxAkbar/ExactFrame/releases/tag/v2.1.1) continue to apply.
